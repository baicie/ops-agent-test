# v0.3 详细设计：Runtime Workspace

- 状态：Planned
- 前置条件：`v0.2` 阶段门禁通过

## 阶段目标

把“调查本机 Demo”扩展为“在明确环境边界内调查真实运行工作空间”。引入 Workspace、只读
Kubernetes、证据化服务拓扑和本地 Runbook，同时保持单进程、单操作者和默认只读。

## 用户结果

用户选择一个 Workspace 并询问某服务异常。Agent 能把 Alert、Metrics、Logs、Traces 与
Kubernetes workload/event 状态关联，展示带来源的服务依赖，并引用匹配 Runbook 给出下一步。
Agent 不能因为选择错误 Workspace、namespace 或 cluster 而越界读取其他环境。

## 范围

### 包含

- 显式 Workspace 模型、配置、Secret 引用和迁移后的 `default` Workspace。
- Kubernetes API read-only connector。
- `k8s_get`、`k8s_events`、`k8s_logs` 三个结构化 Tool。
- 基于当前 Evidence 计算的服务 Topology projection。
- 本地 Markdown Runbook catalog、`runbook_search` 和 `runbook_read`。
- Workspace selector、目标范围和 Topology/Evidence UI。
- Kubernetes 和下游依赖确定性场景。

### 不包含

- 多租户、用户/RBAC、跨 Workspace Thread。
- `kubectl exec`、apply、delete、rollout restart 或其他写操作。
- CMDB、Knowledge Graph、服务发现控制面。
- Runbook RAG、embedding、Vector DB 或自动执行 Runbook。

## Workspace 设计

```text
Workspace {
  id, display_name, environment,
  providers[], connectors[], skills[],
  target_policy, credential_refs,
  budgets, retention, redaction_profile
}
```

Thread 创建后绑定一个 Workspace，不能原地切换。`v0.1-v0.2` Thread 迁移到 `default`。
配置文件只保存 Secret 名称或 keychain reference，不保存 Secret 值。

每个 Event、Evidence、Tool operation、Artifact 和 Audit record 都带 Workspace scope。Runtime
按 Workspace 计算并发、模型成本和 Tool budgets；不能用全局 allowlist 覆盖更严格的局部策略。

## Kubernetes 设计

使用 Kubernetes API client，不通过 `sh -c kubectl`。连接配置来自 kubeconfig context 或
in-cluster Secret reference，Runtime 不把 bearer token 交给模型。

### 允许的能力

- `k8s_get`：读取 allowlist 中的 Namespace、Deployment、StatefulSet、DaemonSet、Pod、Service、
  EndpointSlice、Job 和 Node 摘要。
- `k8s_events`：按 namespace、involved object、reason 和 time window 读取 Event。
- `k8s_logs`：读取 allowlist workload/pod/container 的 bounded logs，不支持 exec 或 attach。

### 强制约束

- Workspace 固定 cluster identity、namespace/resource allowlist 和 label selector 上限。
- API discovery 后再判定 GVK；禁止任意 dynamic resource URL。
- 默认 ServiceAccount 权限使用 Kubernetes RBAC 只读角色，Policy 再做应用层收窄。
- 日志、Secret、ConfigMap data 和 annotation 进入 Evidence 前按 sensitivity/redaction 处理。
- 分页、watch、follow 和无限日志流不在本阶段；每次调用有 time range、limit 和 byte budget。

## Topology 设计

Topology 是带来源和 TTL 的 projection，不是手工维护的事实数据库：

```text
TopologyNode { id, kind, workspace_id, labels, evidence_ids[], observed_at }
TopologyEdge { from, to, relation, confidence, evidence_ids[], observed_at, expires_at }
```

来源优先级为：Trace client/server span > Kubernetes Service/Endpoint/owner reference > Alert/metric
label inference。不同来源冲突时保留两条候选边并显示 confidence，不能静默合并。

`topology_query` 只返回当前 Thread/Workspace 可访问的子图，默认深度 2、节点数有上限。过期边
不进入模型 Context，但可以在 UI 显示为 stale。

## Runbook 设计

Runbook 存放在 Workspace 配置的本地目录，格式为 Markdown 加 YAML front matter：

```yaml
---
id: order-service-db-pool
title: Order service DB pool exhaustion
services: [order-service]
signals: [db_pool_waiting, database_pool_exhausted]
tags: [database, latency]
version: 1
---
```

`runbook_search` 使用元数据过滤和确定性全文索引；`runbook_read` 按稳定 ID/version 读取有界内容。
Skill/Runbook 内的命令只是文本建议，不能自动变成 Tool call。Runbook hash 写入 Evidence，更新后
旧诊断仍能知道当时引用的版本。

## API 与 UI

- `GET /api/v1/workspaces` 返回可用 Workspace 的非敏感摘要。
- 创建 Thread 必须提供 `workspace_id`，本地兼容客户端默认 `default`。
- Thread 页面固定显示当前 Workspace，不能在运行中切换。
- Topology 仅作为调查视图，不做独立 dashboard；Node/Edge 可跳转对应 Evidence。
- Kubernetes ToolCall 显示 cluster alias、namespace、resource 和 selector，不显示 credential。
- Runbook 引用显示版本和 hash，用户可展开原文。

## 实施任务

### Task 1：Workspace 领域与配置迁移

- Acceptance：旧配置生成 `default`；Thread/Event/Evidence 均有 scope；跨 Workspace 访问失败。
- Verify：migration、config validation、scope isolation、secret non-serialization 测试。
- Files：config、runtime model、store projection、server API、tests。

### Task 2：Kubernetes connector 基础

- Acceptance：凭据按引用加载；cluster identity 固定；namespace/GVK/selector policy 强制执行。
- Verify：mock API、RBAC denied、namespace escape、pagination、timeout、redaction 测试。
- Files：新增 connector、config、policy integration、tests、docs。

### Task 3：Kubernetes Tool 垂直切片

- Acceptance：get/events/logs 均产生规范化 Evidence，且没有写 verb 或 shell fallback。
- Verify：schema、allowlist、大日志、Secret data、cancel 和 multi-container tests。
- Files：三个 Tool、registry、Evidence mapping、tests。

### Task 4：Topology projection

- Acceptance：K8s/Trace 来源生成带 Evidence/TTL 的 Node/Edge；冲突和 stale 可见。
- Verify：projection fixture、depth/node limit、source precedence、cross-scope 测试。
- Files：新增 topology domain/projector、API、Tool、tests、Web view。

### Task 5：Runbook catalog

- Acceptance：元数据校验、稳定版本/hash、search/read 和 Context bound 完整。
- Verify：bad front matter、duplicate ID、version change、path traversal、search relevance 测试。
- Files：新增 runbook module/Tools、config、tests、docs。

### Task 6：Workspace 调查体验与场景

- Acceptance：Web/CLI 可选择 Workspace，完整完成 K8s 故障或下游依赖调查。
- Verify：UI interactions、Kubernetes fixture scenario、真实只读 cluster smoke test。
- Files：Web selector/views、CLI flags、scenario、workflow、docs。

## 阶段门禁

- 旧本地 Demo 在隐式 `default` Workspace 下无回归。
- 两个 Workspace 使用不同目标和凭据时，所有跨 scope 请求都被拒绝且有 audit 记录。
- Kubernetes 场景至少关联 workload status、K8s Event 和一类可观测 Evidence，Claim 引用有效。
- Connector 的 Kubernetes RBAC 和应用 Policy 都是只读；测试证明不存在 write verb。
- Topology 中每条边都有 Evidence 和 TTL，过期/冲突不会被当成确定事实。
- Runbook 内容不能绕过 Tool Registry、Policy 或 Approval。
- Secret/ConfigMap 敏感数据不进入模型、telemetry 或默认 UI。
- `just release-check`、Workspace/K8s 场景和真实 Provider gate 通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| kubeconfig 权限大于应用 allowlist | 高 | 双层约束、最小 RBAC、解析后 target check |
| Topology 被误当成权威 CMDB | 中 | Evidence/TTL/confidence 强制字段，明确 projection |
| K8s 对象和日志泄露 Secret | 高 | 字段 allowlist、敏感资源默认禁止、redaction tests |
| Runbook 中有恶意指令 | 中 | 内容只作为不可信参考，执行仍经过 Tool/Policy |
| Workspace 引入范围迁移错误 | 高 | default migration fixture 和跨 scope property tests |
