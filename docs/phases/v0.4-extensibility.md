# v0.4 详细设计：Extensibility

- 状态：实现中
- 前置条件：`v0.3` 阶段门禁通过

## 阶段目标

允许用户在不修改 Runtime 核心的情况下增加受约束的 Tool 和领域指令，同时保持 Workspace、
Evidence、预算和 Policy 不可绕过。支持 MCP、进程外 Custom Tool 和 Skill，但不建立插件市场。

## 用户结果

用户可以在一个 Workspace 中显式安装、配置和启用扩展。Agent 看到的是统一 Tool schema 和
Skill 内容；用户看到扩展来源、版本、权限和健康状态。扩展崩溃、超时或返回恶意内容时，
Runtime 能隔离失败且不会泄露凭据或扩大权限。

## 范围

### 包含

- `CapabilityDescriptor` 和受控 Extension Registry。
- MCP client：本地 stdio 与受信 Streamable HTTP transport。
- 进程外 Custom Tool manifest/runner。
- 本地 Skill package：Markdown 指令、metadata 和只读 resources。
- 安装/启用/禁用、版本 pin、健康检查和兼容校验。
- Workspace scope、Policy、Evidence、redaction、timeout 和 cancellation 集成。
- Prompt Injection、资源耗尽和 schema 欺骗测试。

### 不包含

- 在线 marketplace、自动下载、自动升级或第三方代码签名服务。
- 进程内动态 Rust library、WASM runtime 或任意脚本加载。
- Skill 自动执行；Skill 只能影响 Context，不能直接调用系统能力。
- Multi-Agent 或扩展自己的 Agent Loop。

## 统一能力描述

所有内建和外部 Tool 归一化为：

```text
CapabilityDescriptor {
  id: namespace/name@version,
  source: builtin | mcp | custom,
  input_schema,
  output_schema,
  effect,
  target_requirements,
  budgets,
  recovery,
  provenance,
  content_sensitivity
}
```

扩展声明是上限，不是授权。最终 effect 取扩展声明、Workspace policy 和本地 override 中最严格
结果；外部扩展不能把 change 声明成 observe 来降低审批等级。缺少 effect 或 recovery metadata
的 Tool 默认 `external_side_effect` 并被拒绝，直到用户补充本地 override。

Tool name 必须使用 namespace，内建命名空间保留。schema 和 descriptor hash 参与 Model Context、
Approval 和 Audit，运行中改变版本或 schema 会使未完成批准失效。

## MCP 设计

- stdio server 由受控 supervisor 启动，使用最小环境变量、固定 cwd、resource limits 和独立 stderr。
- Streamable HTTP endpoint 必须在 Workspace allowlist，强制 TLS；认证使用 Secret reference。
- 初始化后记录 server identity、protocol version、tool list 和 schema hash。
- 每次调用映射为普通 Tool operation，仍经过参数规范化、Policy、timeout、output bound、redaction 和
  Evidence conversion。
- notifications、resources 和 prompts 默认禁用；后续启用需独立 Capability 和 ADR。
- server 断开不自动无限重启；使用 bounded backoff 和 circuit breaker，失败回灌模型。

MCP 返回内容是不可信数据，不能覆盖 System Instructions、Workspace policy 或 Tool effect。

## Custom Tool 设计

Custom Tool 是一个 manifest 加进程外可执行程序：

```yaml
apiVersion: opscodex.dev/v1
kind: Tool
metadata:
  name: acme/service-status
  version: 1.2.0
spec:
  command: /absolute/path/service-status
  inputSchema: ./input.schema.json
  outputSchema: ./output.schema.json
  effect: observe
  timeoutSeconds: 10
  maxOutputBytes: 65536
```

runner 通过 stdin/stdout 交换单个 JSON object，不通过 shell。环境变量使用 allowlist，Secret 通过
一次性文件描述符或 runner 支持的 secret channel 注入。manifest 路径、binary hash、schema hash
和签发来源进入 provenance。

本阶段不提供强 sandbox 保证；未配置 OS 隔离时 Custom Tool 只允许用户标记为 trusted-local，
并清晰显示风险。远程或生产 Workspace 可以禁止 Custom Tool。

## Skill 设计

Skill package 包含：

```text
skill-id/
  SKILL.md
  references/
  resources/
```

metadata 声明 ID、version、适用 service/tag、需要的 Tool capability、最大 Context bytes 和 hash。
Skill 选择先用 metadata 确定性过滤，再把所需片段放入 Context；不扫描整个目录，也不使用 Vector DB。

Skill 文本和 resources 是不可信内容，只能补充调查方法。它们不能：

- 改写 System/Policy 指令。
- 注册 Tool 或获得 Secret。
- 绕过 Workspace target scope。
- 直接执行其中的命令。

## 生命周期

```text
discovered -> validated -> configured -> enabled -> healthy
                         \-> disabled
enabled/healthy -> degraded -> disabled
```

发现不会自动启用。启用需要固定版本/hash、Workspace 和本地 policy。Runtime 启动时校验 manifest、
schema、路径、endpoint 和冲突；失败扩展不能阻止未依赖它的 Workspace 启动。

## API 与 UI

- API 只公开非敏感 descriptor、health、version 和 enable state。
- 安装和修改配置仍是本地文件操作，不通过无认证 Web API 完成。
- Thread 显示每个 Tool 的来源和版本；外部扩展使用明确标识。
- Skill 展示被加载的名称/version 和 Context bytes，不展示隐藏模型推理。
- 扩展失败显示可恢复状态，不将 stderr 原文直接暴露给模型或默认 UI。

## 实施任务

### Task 1：Capability Descriptor 与 Registry

- Acceptance：内建 Tool 也使用统一 descriptor；namespace/version/schema hash 稳定；冲突失败关闭。
- Verify：descriptor fixture、duplicate、schema change、strictest-effect 和 compatibility tests。
- Files：Tool trait/registry、policy、config、tests、docs。

### Task 2：Extension lifecycle 与 supervisor

- Acceptance：扩展显式启用、可健康检查、bounded restart、取消时清理子进程。
- Verify：crash loop、hang、large stderr、shutdown、resource budget tests。
- Files：新增 extension registry/supervisor、app composition、tests、telemetry。

### Task 3：MCP Tool 垂直切片

- Acceptance：stdio/HTTP server 的 Tool 可调用并生成标准 Evidence，不能绕过 Workspace/Policy。
- Verify：protocol fixture、TLS/allowlist、auth redaction、schema mutation、timeout tests。
- Files：新增 MCP adapter/config、registry integration、tests、docs。

### Task 4：Custom Tool runner

- Acceptance：无 shell JSON runner、manifest 校验、最小 env、output schema 与 provenance 完整。
- Verify：path traversal、invalid JSON/schema、env leak、binary hash change、cancel tests。
- Files：新增 manifest/runner、registry integration、tests、docs。

### Task 5：Skill loader

- Acceptance：metadata 选择和 bounded loading 可重复；Skill 不能引入新 capability 或 Secret。
- Verify：malicious instruction、symlink/path escape、large resource、version/hash tests。
- Files：新增 skill module/context integration、tests、docs。

### Task 6：扩展管理体验和安全场景

- Acceptance：CLI/Web 可解释扩展来源、健康和失败；安全 fixture 全部被隔离。
- Verify：UI/CLI tests、Prompt Injection/资源耗尽 scenario、真实 MCP smoke gate。
- Files：CLI、Web components、scenario/verifier、workflow、docs。

## 阶段门禁

- 内建、MCP、Custom Tool 通过同一 Tool contract 和 Evidence tests。
- 外部扩展不能降低 effect、扩大 target 或读取未声明 Secret。
- 扩展崩溃、卡死、输出超限和 schema 变化不会破坏 Runtime 或其他 Thread。
- Prompt Injection fixture 不能改变 System/Policy，禁止动作数为 0。
- Skill 加载可解释、可重现且在 Context budget 内。
- 所有启用扩展有来源、版本和 hash；未 pin 的扩展不能进入发布 Workspace。
- `just release-check`、扩展安全场景和真实 Provider gate 通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| MCP/Skill 内容诱导越权 | 高 | 内容不可信、Policy 独立、Prompt Injection suite |
| Custom Tool 进程访问宿主资源 | 高 | 默认禁用、最小 env、生产 Workspace 可禁止、后续 sandbox |
| schema/version 漂移破坏审批 | 高 | descriptor hash、version pin、变化使批准失效 |
| 扩展数量放大 Context | 中 | capability selection 和 schema budget |
| transport 故障拖慢 Turn | 中 | timeout、circuit breaker、剩余预算 |
