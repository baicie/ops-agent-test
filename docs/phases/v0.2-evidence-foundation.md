# v0.2 详细设计：Evidence Foundation

- 状态：实现中
- 前置条件：`v0.1.0` 已发布

## 阶段目标

在增加 Logs、Trace 和 Alert 数据量之前，稳定 Event、Evidence、Claim、Provider 和数据治理
合同。阶段完成后，Agent 能从 Alert Context 出发，跨 Metrics、Loki Logs 和 Tempo Traces
形成机器可验证的 Evidence-linked Diagnosis。

## 用户结果

用户提交一个包含 service、environment、time window、labels 和 annotations 的告警。OpsCodex
自动建立调查范围，查询至少三类信号，在统一时间线上展示 Evidence，并在最终 Diagnosis 中
引用稳定 Evidence ID。若某一数据源不可用，Agent 明确降级并说明结论限制。

## 范围

### 包含

- Event schema v2 和旧 JSONL 兼容读取。
- `EventStore` trait、投影契约和独立 Turn 查询模型。
- 稳定 Evidence ID、Claim、Artifact、Sensitivity 和内容哈希。
- 多预算 Context Builder：token、bytes、Evidence 数、Tool calls 和估算成本。
- Provider capability 声明和统一契约测试。
- Alert/Incident Context。
- Loki `log_query`，Tempo `trace_search` 与 `trace_get`。
- Runtime metrics、可选 OTLP trace 和默认脱敏。
- 多信号场景评测与引用校验器。

### 不包含

- Kubernetes、Topology 和 Runbook。
- 完整摘要压缩、Thread Fork 或进程重启续跑。
- MCP、Custom Tool、Skill。
- 任何环境变更操作。

## 领域模型变化

### EventEnvelope v2

```text
schema_version = 2
stream_kind = domain | delivery
event_id
seq
workspace_id = "default"
thread_id
turn_id?
item_id?
causation_id?
timestamp
event
```

`seq` 仍是 Thread 内 SSE 游标。`event_id` 提供跨导出和迁移的稳定身份；`causation_id` 把
Model step、Tool proposal、result 和 Claim 串联起来。v1 客户端必须忽略未知可选字段。

状态转换、完成 Item、Evidence 和 Approval 使用 `domain`；Assistant delta、进度和 heartbeat 使用
`delivery`。两者都先持久化再广播，但只有 domain stream 重建权威状态。完成消息落盘并经过配置的
兼容窗口后可以清理 delivery payload，不能复用其 `seq`。

`ToolStarted` 演进为 `ToolProposed`、`ToolAuthorized`、`ToolExecutionStarted` 和
`ToolCompleted`，避免审批前显示为已经执行。v0.1 事件读取时映射为兼容投影。

### EvidenceRecord

```text
evidence_id
source_kind
source_ref
query_or_operation
observed_at / time_range
summary
artifact_ref?
content_type
byte_size
truncated
sensitivity
sha256
```

小结果可以内联，大结果写入按内容寻址的本地 artifact。Artifact 有独立 byte limit、MIME、
retention 和读取 API；模型上下文只接收必要摘要，不自动接收完整原文。

### Diagnosis 与 Claim

最终输出先由 Runtime 解析为结构化 Diagnosis，再渲染为 Markdown：

```text
summary
claims[] { claim_id, kind, statement, evidence_ids[], confidence }
recommended_actions[]
limitations[]
```

`observed` Claim 至少一个 Evidence；`inferred` Claim 至少一个 Evidence 并明确是推断；
`recommended` 可以无直接 Evidence，但必须关联 Diagnosis。精确数值置信度改为 low/medium/high。

## Incident Context

创建 Thread 或 Turn 时可带：

```json
{
  "service": "order-service",
  "environment": "staging",
  "starts_at": "2026-08-16T00:00:00Z",
  "ends_at": "2026-08-16T00:15:00Z",
  "labels": {"severity": "critical"},
  "annotations": {"summary": "5xx rate high"},
  "source": {"kind": "alertmanager", "fingerprint": "..."}
}
```

输入限制、允许字段和敏感级别在 API 层校验。Alert Context 是调查提示，不自动成为 Evidence；
Agent 必须通过 Tool 验证其中的陈述。

## Connector 设计

### Loki

`log_query` 使用 Loki `query_range`，参数必须包含受限时间窗、query、limit 和 direction。
Workspace 配置固定 base URL、tenant header 的 Secret 引用和最大查询范围。返回结果规范化为带
stream labels、timestamp 和 bounded lines 的 Evidence。

### Tempo

OpsCodex 不接收 OTLP，也不成为 Trace backend。`trace_search` 查询 Tempo 搜索接口，
`trace_get` 按 trace ID 获取受限摘要。默认只把 span name、service、status、duration 和必要
attributes 放入上下文；完整 Trace 作为 artifact 保存。

### 错误与降级

Connector 错误分类为 auth、rate_limit、timeout、unavailable、invalid_query 和 malformed_data。
错误作为非 Evidence ToolResult 回灌模型。重试仅适用于明确 retryable 的只读调用，使用指数退避、
jitter 和 Turn 剩余预算。

## Context 与数据治理

- Context Builder 按 token/byte 双预算选择 Item，不再只按数量裁剪。
- Tool call/result 必须成对；关键 Evidence 和当前 Incident Context 优先保留。
- 每个 Tool 输出先做 size bound、字段 allowlist 和 Secret/PII pattern redaction。
- telemetry 只记录 Tool 名、分类、bytes、latency、status 和 hash，不记录 query/result 原文。
- Thread/Event/Artifact 使用明确目录权限和 retention 配置。
- 本阶段只做选择与截断，完整可重用 Summary/Compaction 留到 `v0.5`。

## API 与 UI

- 新 API 使用 `/api/v1`；旧路由保持一个兼容周期。
- Thread detail 默认分页返回 domain event，delivery delta 可单独请求。
- Evidence endpoint 按 ID 返回 metadata；artifact 内容需显式展开且受 byte range 限制。
- Web 将 Alert Context、Evidence timeline、Claim 引用和 Limitations 分开显示。
- 点击 Claim 可定位到对应 Evidence；来源不可用或内容已过 retention 时显示明确状态。

## 实施任务

### Task 1：Event schema v2 与投影合同

- Acceptance：新 Event 有稳定 ID/version/causation；旧 v0.1 Thread 可无损读取；Rust/Web 投影一致。
- Verify：schema fixture、旧日志 replay、SSE reconnect、unknown-field compatibility 测试。
- Files：`src/runtime/event.rs`、`src/runtime/thread.rs`、`web/src/types.ts`、`web/src/reducer.ts`、tests。

### Task 2：抽象 EventStore

- Acceptance：Runtime 不再依赖具体 `JsonlStore`；append/read/checkpoint 使用明确 trait；行为不变。
- Verify：JSONL contract suite、并发 seq、partial-tail 和 store-failure 测试。
- Files：`src/store/mod.rs`、`src/store/jsonl.rs`、`src/runtime/agent.rs`、`src/app.rs`、tests。

### Task 3：Evidence、Claim、Artifact 与 Redaction

- Acceptance：每个成功 ToolResult 生成稳定 Evidence；Claim 引用可机器校验；大输出外置有界存储。
- Verify：hash、retention、redaction、invalid citation、truncation 和 round-trip 测试。
- Files：新增 `src/evidence/`，调整 Event/Runtime/Server 与对应 tests。

### Task 4：Provider capability 与契约测试

- Acceptance：Provider 声明实际能力；不支持的配置启动失败；Responses adapter 通过公共 suite。
- Verify：stream/tool/usage/cancel/reasoning/error/EOF fixture matrix。
- Files：`src/model/provider.rs`、`src/model/openai.rs`、`src/config.rs`、tests。

### Task 5：Incident Context 垂直切片

- Acceptance：CLI/API/Web 可提交、持久化和显示 Context；Context 不被误计为已验证 Evidence。
- Verify：input bound、schema、projection、prompt mapping 和 UI tests。
- Files：Runtime model、Server routes、CLI、Web API/UI、tests。

### Task 6：Loki 垂直切片

- Acceptance：受限范围日志查询产生规范化 Evidence；认证信息不进入事件；失败可降级。
- Verify：fixture server、limit/time range、tenant secret、timeout、malformed response 测试。
- Files：新增 Tool、config、registry、tests、docs。

### Task 7：Tempo 垂直切片

- Acceptance：Trace 搜索和详情产生有界摘要及 artifact；不实现 OTLP ingestion。
- Verify：fixture server、attribute redaction、large trace、timeout、not-found 测试。
- Files：新增 Tools、config、registry、tests、docs。

### Task 8：Evidence-linked UI 与评测

- Acceptance：Claim 可定位 Evidence；场景评分器验证引用、abstain 和无证据 Claim。
- Verify：React interaction tests、多信号 deterministic scenario、真实 Provider smoke gate。
- Files：Web components/reducer、scenario fixtures、verifier、workflow、docs。

## 阶段门禁

- 旧 `v0.1` JSONL、API 主路径和 Demo 回归全部通过。
- Alert Context -> Prometheus -> Loki -> Tempo -> Diagnosis 场景可重复通过。
- 所有 observed/inferred Claim 引用存在且 hash 匹配的 Evidence，无来源 Claim 为 0。
- 任一 Connector 故障时，Turn 能继续或明确 abstain，不伪造缺失数据。
- Secret/PII 注入 fixture 不出现在 telemetry、SSE 默认视图或 CI artifact。
- Context 大小在配置预算内，Tool call/result 不被裁成孤立项。
- Runtime metrics 暴露 queue、turn、model、tool、store、SSE lag；label 无高基数 ID。
- `just release-check`、多信号 scenario 和真实 Provider release gate 通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Event v2 同时影响存储、API、UI | 高 | 先写 fixture 和兼容 reader，再改 producer |
| Logs/Trace 迅速放大上下文 | 高 | artifact 外置、摘要、token/byte 双预算 |
| Provider 兼容端点行为不同 | 中 | capability 声明和公共 contract suite |
| Redaction 误删诊断信息 | 中 | 字段 allowlist、可见 redaction 标记、fixture 测试 |
| LLM 输出不满足结构 | 中 | schema response 或严格 parser；失败时保留文本并标为 unverified |
