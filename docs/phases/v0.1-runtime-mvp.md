# v0.1 详细设计：Runtime MVP

- 状态：Released
- 版本：`v0.1.0`
- 发布提交：`ec0bf0db148c7329d78e32921fbde6770c1adf70`
- 发布日期：2026-08-16

## 阶段目标

用最小基础设施证明一个 Rust 自研 Agent Runtime 可以完成真实的
`Model -> Tool -> Evidence -> Model -> Diagnosis` 闭环，并通过 CLI 和 Web 暴露同一会话。

唯一发布场景是 `order-service` 数据库连接池耗尽：Agent 必须发现 5xx、P95、容器日志和
健康状态之间的关联，给出数据库连接池耗尽的主诊断。

是默认关闭且每次需要批准的本地开发 escape hatch，不是自动 remediation。

## 领域与执行设计

- `Thread` 是持续调查会话，使用 UUID v7。
- 每次用户输入创建一个 `Turn`；同一 Thread 最多一个 active Turn。
- Runtime 以最多 12 个 model step 执行，模型无 ToolCall 时完成。
- 工具结果无论成功或失败都转成 `ToolCompleted` 并回灌模型。
- 模型超时 120 秒，工具超时 30 秒，单次输出最多 64 KiB。
- 全局最多 4 个并发 Turn，CancellationToken 贯穿排队、模型、审批和工具。
- 所有 Event 先 append JSONL，再通过 broadcast/SSE 发布。

## 模型设计

Runtime 只依赖内部 `ModelProvider`、`ModelRequest`、`ModelOutput` 和 `ModelEvent`。
`OpenAIResponsesProvider` 负责 Responses wire mapping，支持：

- 流式文本 delta。
- function call 和 `function_call_output` 回灌。
- response ID 和 token usage 解析。
- 供应商错误、超时和取消。
- 可选 `reasoning_effort`；release provider 使用 `none`，不持久化隐藏推理。

## Tool 与安全设计

| Tool | Effect | 默认策略 | 目标限制 |
| --- | --- | --- | --- |
| `promql_query` | Observe | Allow | 固定 Prometheus base URL |
| `docker_logs` | Observe | Allow | `allowed_containers` |
| `http_get` | Observe | Allow | `allowed_hosts`，禁凭据与重定向 |
| `exec` | Unknown | Ask | 默认不注册 |

每个 Tool 提供 JSON Schema、风险等级、取消和 EvidenceMeta。Unknown Tool、越界目标和拒绝审批
都作为失败工具结果记录，模型不能把它们当成成功证据。

## Event、存储与 SSE

每个 Thread 对应一个 append-only JSONL。`EventEnvelope.seq` 在 Thread 内单调递增；残缺尾行
在读取时忽略并在下次 append 前修复，完整坏行拒绝加载。

JSONL Event 是事实源，Thread、Model history 和 UI timeline 都是投影。模型历史忽略 delta，
只使用完成消息和成对的 ToolCall/ToolResult。

SSE 建立时先订阅 live channel，再读取 `after` 或 `Last-Event-ID` 之后的 durable Event；live
event 按 `seq` 去重。broadcast lag 时从 JSONL 补读，因此不需要消息队列。

## Demo 验收

Docker Compose 只包含 `order-service` 和 Prometheus。order-service 自带确定性流量，并支持：

- `normal`
- `errors`
- `latency`
- `db-pool`

`db-pool` 必须同时产生非零 5xx、P95 大于 2 秒、idle connection 为 0、waiting 大于 0、
`degraded/db-pool` 健康状态、HTTP 500 和 `database pool exhausted` 日志。

## 已知限制

- active Turn、ApprovalBroker、EventHub 和并发 lease 都在进程内，重启后不能续跑。
- JSONL 每次 append 重读整个 Thread，并用全局 mutex 串行化，不能支撑长期大 Thread。
- Context 按 item 数裁剪，不按 token、bytes、Evidence 优先级或成本预算。
- Evidence 没有稳定 ID；最终答案引用是文本约定，不是机器可校验关系。
- Event 没有 schema version，Rust 与 TypeScript 类型需要人工同步。
- Policy 只按静态 ToolRisk 判断，不理解参数、目标或 effect。
- 无 Runtime metrics、OTLP、自身 readiness、数据保留和本地 Evidence 脱敏策略。
- 未认证 Server 只适合 loopback，不支持远程多用户部署。

以上限制分别由 `v0.2`、`v0.3` 和 `v0.5` 处理。不得通过增加提示词掩盖状态、存储或安全缺陷。
