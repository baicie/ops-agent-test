# v0.5 详细设计：Continuity

- 状态：实现中
- 前置条件：`v0.4` 阶段门禁通过；Event schema v2 和 EventStore port 稳定

## 阶段目标

让长时间调查在 Context 增长、进程重启和分支探索下仍然正确。交付 SQLite 事实源、持久
checkpoint/approval/lease、Context Compaction、Thread Fork 和显式 Resume。

## 用户结果

用户可以压缩一个长 Thread、从任意安全 checkpoint fork 调查方向，并在进程重启后继续等待
审批或恢复调查。系统能明确区分“可安全重试”和“外部结果未知”，绝不因恢复而双重执行写操作。

## 范围

### 包含

- SQLite WAL 默认存储和 JSONL 导入/导出。
- Event、Item/Projection、Artifact metadata、Checkpoint、Approval、Lease schema。
- 事务 append、分页、索引、备份和迁移校验。
- 多预算 Context Compaction 和 Summary provenance。
- Thread Fork 与 parent lineage。
- 进程启动 recovery scan、显式 Resume 和 `NeedsReconciliation`。
- 崩溃边界 fault injection suite。

### 不包含

- PostgreSQL、消息队列、分布式 scheduler 或多实例并发。
- exactly-once 外部副作用承诺。
- 自动解决 `NeedsReconciliation`。
- Multi-Agent 分支合并。

## SQLite 设计

默认文件：`~/.opscodex/state.sqlite3`，artifact 仍存放在内容寻址目录。核心表：

```text
workspaces(id, ...)
threads(id, workspace_id, parent_thread_id, forked_at_seq, ...)
turns(id, thread_id, status, active_lease_id, ...)
events(thread_id, seq, event_id, schema_version, payload, timestamp, ...)
items(item_id, thread_id, turn_id, kind, projection_data, ...)
evidence(evidence_id, thread_id, artifact_ref, sha256, ...)
checkpoints(checkpoint_id, turn_id, step, state, input_hash, ...)
approvals(approval_id, operation_id, request_hash, status, expires_at, ...)
leases(lease_id, turn_id, owner_id, expires_at, fencing_token)
schema_migrations(version, checksum, applied_at)
```

Event 是事实源，items/evidence/turns 是可重建投影或带校验的索引。一次状态变化在同一事务写入
Event、checkpoint 和必要投影，然后才向 SSE 发布。SQLite 使用单 writer、busy timeout 和 WAL；
不支持多个 OpsCodex 进程共享同一文件。

## JSONL 迁移

1. 锁定本地 store，扫描并校验所有 Thread。
2. 为 v0.1 Event 确定性生成 event ID 和 `default` Workspace。
3. 在单事务按 Thread/seq 导入，重建投影并比较事件数、首尾 seq 和内容 hash。
4. 原 JSONL 移到带时间戳的只读 backup，不立即删除。
5. 原子切换 store marker；失败时保留 JSONL 为 active source。

迁移命令支持 `--dry-run`、`--verify` 和重复执行。导出命令始终可生成一 Thread 一 JSONL 的
人类可读记录，但不导出 Secret。

## Checkpoint 与恢复语义

每个 model/tool 边界写 durable checkpoint：

```text
step
phase
context_input_hash
provider_checkpoint?
pending_operation?
last_committed_seq
resume_policy
```

启动时 recovery scan 处理非终态 Turn：

- `queued/model_running`：标为 `interrupted`，用户 Resume 后从最后规范化 Context 重发模型请求。
- `waiting_approval`：恢复 pending approval；过期批准自动 rejected，不执行 Tool。
- `tool_running + observe`：使用 operation ID 可安全重试，或先查询 connector 状态。
- `tool_running + change`：进入 `needs_reconciliation`，不能自动重试。
- 已落 ToolResult：从下一 model step 继续，不能重复执行 Tool。

Lease 仅防同一 SQLite store 内双执行，带 fencing token 和短 TTL。它不声称分布式一致性。

## Context Compaction

当 token/byte/cost watermark 到达阈值时生成 `SummaryItem`：

```text
summary_id
covers_seq_start / covers_seq_end
source_item_ids[]
source_evidence_ids[]
input_hash
model_provider / model / prompt_version
summary
created_at
```

原 Event、Item 和 Evidence 不删除；Context Builder 用 Summary 替代覆盖范围。摘要必须保留未解决
问题、关键 Evidence ID、工具失败、批准结果和用户约束。摘要模型失败时继续使用 bounded suffix，
不能阻塞 Thread 读取。

## Thread Fork

Fork 只能发生在 durable `seq`，新 Thread 记录 `parent_thread_id` 和 `forked_at_seq`。Fork 继承：

- Workspace 和只读配置 snapshot。
- 该 seq 之前的可见 Item/Evidence 引用。
- 可覆盖相同范围的有效 Summary。

Fork 不继承 active Turn、pending approval、lease 或 Action。父子后续完全独立；本阶段不支持 merge。

## API 与 UI

- `POST /api/v1/threads/:id/forks` 接受 `at_seq` 和可选 title。
- `POST /api/v1/turns/:id/resume` 需要 Idempotency-Key，并返回 resume operation。
- `GET /api/v1/turns/:id/recovery` 解释可恢复阶段、风险和需要的用户动作。
- Web 显示 lineage、compaction、interrupted 和 needs-reconciliation 状态。
- Resume 前展示从哪个 checkpoint 开始、哪些 Tool 不会重复执行。

## 实施任务

### Task 1：SQLite EventStore

- Acceptance：事务 append、分页、投影和 SSE 行为与 JSONL contract 一致，写性能不随 Thread 全长线性增长。
- Verify：shared contract suite、concurrency、busy/IO failure、crash-after-commit tests。
- Files：新增 SQLite store/schema、store port、app config、tests、docs。

### Task 2：JSONL migration/backup/export

- Acceptance：迁移可 dry-run、重复、校验和回滚；所有旧 Thread ID/seq/content 保留。
- Verify：v0.1 fixtures、partial tail、bad line、interrupted migration、round-trip tests。
- Files：migration module/CLI、JSONL importer/exporter、tests、docs。

### Task 3：Checkpoint、Lease 与 durable Approval

- Acceptance：每个边界有 checkpoint；同 Turn 只有有效 fencing owner；审批重启后可继续或过期。
- Verify：crash matrix、lease expiry、double resume、approval replay/expiry tests。
- Files：runtime coordinator、store schema、policy broker、server API、tests。

### Task 4：Recovery 与 reconciliation

- Acceptance：各非终态按照 effect 进入 retry/resume/reconcile；写操作未知时绝不自动重试。
- Verify：每个 checkpoint 前后 kill-process fault injection 和 operation count assertions。
- Files：recovery module/runtime、Tool operation model、API/UI、tests。

### Task 5：Context Compaction

- Acceptance：长 Thread 在预算内，摘要可追溯且保留关键 Evidence/约束；原始事实可审计。
- Verify：token/byte thresholds、summary failure、evidence retention、deterministic fixture tests。
- Files：context builder/summary model/store、tests、UI metadata。

### Task 6：Thread Fork

- Acceptance：任意 durable seq 可 fork；继承内容准确；active state 不泄露；父子独立追加。
- Verify：lineage、boundary seq、compacted parent、cross-workspace rejection tests。
- Files：thread domain/store/API/CLI/UI/tests。

## 阶段门禁

- JSONL -> SQLite -> JSONL round-trip 的语义 Event 和 hash 一致。
- 所有持久化边界的 kill-process tests 都得到唯一、安全且解释清楚的终态。
- 已完成 Tool operation 不重复；不确定写操作全部进入 `NeedsReconciliation`。
- Approval 重启后仍绑定原 request hash，过期或参数变化不能执行。
- 10 倍当前最大 fixture 的 Thread 仍在 Context budget 内并可分页浏览。
- Fork 的 inherited Evidence/summary/lineage 可复核，父子没有 active state 共享。
- 备份、迁移失败回滚和磁盘满场景有操作文档。
- `just release-check`、recovery fault suite 和真实 Provider gate 通过。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 迁移损坏用户历史 | 高 | dry-run、hash 校验、只读 backup、原子 marker |
| 恢复导致 Tool 双执行 | 高 | operation ID、effect-aware policy、checkpoint、reconciliation |
| 摘要丢失关键约束 | 高 | source refs、必保留字段、原始事实不删除、fixture suite |
| SQLite 多进程误用 | 中 | owner lock、启动 fail-fast、文档明确单进程 |
| Fork 引入隐性共享状态 | 中 | 只继承 immutable refs，不继承 lease/approval/action |
